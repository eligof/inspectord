## Known break

`crates/inspectord_native_bpf/src/main.rs:13` imports
`aya_ebpf::helpers::gen::bpf_probe_read_user as raw_probe_read_user`.

Ground truth from the vendored crate source (`aya-ebpf-0.2.1/src/helpers.rs:19`):

```rust
pub use aya_ebpf_bindings::helpers as generated;   // 0.2.x
pub use aya_ebpf_bindings::helpers as gen;         // 0.1.x
```

The module was renamed `gen` -> `generated` (`gen` became a reserved keyword in
Rust edition 2024). The raw helper's signature is byte-for-byte identical in
`aya-ebpf-bindings-0.2.0/src/x86_64/helpers.rs:1156`:

```rust
pub unsafe fn bpf_probe_read_user(
    dst: *mut c_void, size: __u32, unsafe_ptr: *const c_void,
) -> c_long
```

So the fix is a **rename only** — no semantic change, no loss of the
runtime-length read.

### Why the raw helper must stay

`process_exec` copies `mm->arg_start .. mm->arg_end` with a runtime-computed
length capped at `CMDLINE_LEN`. The safe wrapper `bpf_probe_read_user_str_bytes`
stops at the first NUL, i.e. `argv[0]` only, which defeats the LOLBin detection
that consumes this field (the suspicious string lives in `argv[2]` of an outer
`bash -c '...'`). Do not "simplify" this away.

## Other surfaces to check

- `aya-build` 0.2.0: `Package` struct and `build_ebpf(packages, toolchain)`
  signature are unchanged (verified by diffing 0.1.3 vs 0.2.0 `src/lib.rs`).
  Behavioural deltas: honours `AYA_BUILD_SKIP`, tolerates a missing `rustup`,
  only passes `-Z build-std=core` on a nightly rustc, and moved the nested
  `--target-dir` under `OUT_DIR/aya-build/target/<pkg>`. `emit_bpf_target_arch_cfg`
  now returns `Result` — we do not call it.
- `aya` 0.14 userspace surface used by `loader.rs`: `include_bytes_aligned!`,
  `maps::{ring_buf::RingBuf, Array, MapData}`, `programs::{BtfTracePoint,
  TracePoint}`, `Btf`, `Ebpf`, `util::online_cpus`, `EbpfError`, `ProgramError`,
  `BtfError`. `online_cpus()` keeps its `Result<Vec<u32>, (&'static str,
  io::Error)>` shape. Anything else that moved will surface as a compile error;
  resolve each against the vendored 0.14.0 source, not from memory.
- `aya-ebpf` 0.2 program/map surface: `RingBuf::reserve/submit`, `Array::get`,
  `BtfTracePointContext::arg`, `TracePointContext::read_at`, the
  `#[btf_tracepoint]` / `#[tracepoint]` / `#[map]` macros.
